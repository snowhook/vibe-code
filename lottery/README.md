## 几个必须记住的坑

1. **nginx 必须用 `location ^~ /lottery/`**
   站点里有 `location ~* \.html$` 正则，普通前缀会被它抢先匹配，导致 404。`^~` 优先级高于正则。

2. **镜像补号必须只插新行**（`store.upsert_draws(rows, only_new=True)`）
   服务器在新加坡，官方源取不到（福彩 403 网宿 WAF、体彩 567），走 500.com 镜像。
   镜像**没有销售额/奖池**，若覆盖写会把已有的官方富数据抹成 0。

3. **镜像号码串不能用官方的 `_toks` 拆**
   官方 cwl 的紧凑格式（如 `"280"`）需要按位拆；镜像的七乐彩特别号 `"23"` 是**一个**号码，
   按位拆会变成 `2`+`3`。镜像路径用 `_toks_ball`。

4. **500.com 路径 slug ≠ 彩种代码**
   `3d→sd`、`pl3→pls`、`pl5→plw`；七乐彩走 `newinc` 页，其余数字型走 `inc` 页。
   数据源改版时先用 `deploy/probe_chart.py` 重新探测列布局，不要猜。

## 2026-10-13 傍晚 改动：AI 建议报「未接入模型」＋ 自选池交互改造

### 报「未接入大模型」：不是 Key 没配，是开关没打开

`GET /api/options` 的 `llm` 段是 `has_key: true` 但 `enabled: false` —— Key 早配好了，
只是设置页「启用」下拉还停在「关闭」；`llm.chat()` 第一句就是 `if not cfg.get('enabled'): return None`，
请求根本没发出去。**「配了却不生效」优先怀疑有没有第二个开关，别先怀疑 Key 或网络。**

修两处（别只修一半）：

1. **配置**：`enabled` 置 `true`（`POST /api/settings/llm {config:{enabled:true}}`），实测 DeepSeek 正常返回。
2. **防呆**：`llmHint()` 把错误翻成人话（「去『设置 → 大模型配置』把『启用』切到『开启』并保存」）；
   `saveLLM()` 保存后也会回报「已保存，但『启用』是关闭 —— AI 建议仍不可用」。

### 自选池交互：选区 ↔ 池 分离

原来「清空」一个按钮同时清掉**选区**和**自选池**；「确认投注并记账」之后选区又**不**自动清空 ——
「选一注 → 记账 → 再选第二注」这个最自然的流程很不顺手。

| 交互 | 之前 | 现在 |
|---|---|---|
| 选区 → 池 | 只有「确认投注并记账」一次到位 | 新增 **「＋ 加入自选池」**：选区作为一注存入下方，**选区自动清空** |
| 清空 | 一个「清空」，连池一起清掉 | 拆成 **「清空选区」** 与 **「清空自选池」**，互不牵连 |
| 池内单注删除 | 无 | 每注右侧 **×** 单独删除 |
| 记账后 | 选区残留，像是没保存 | `doBet()` 成功后一并清空选区 |
| 未入池的选区 | 与池内一注长得一样，分不清 | 多一行虚线框的「选区预览 · 未加入」行 |

号码不足时点「加入自选池」给具体提示（如「红球 至少选 6 个（当前 2 个）」），不会把半注塞进池。
顺手加了内联 SVG favicon（🎯），消掉浏览器自动请求 `/favicon.ico` 的 404。

### 本轮验证

无头 Chrome 真点线上页面 **22/22，连跑两遍**：登录 → 选号 → 加入自选池 → 选区归零 → 再加一注 →
单注删除（核对删的是哪一注）→ 清空 → 清空选区不误伤池 → 号码不足护栏 → 无 JS 异常 / 失败请求。

> **测试坑**：`#p-tickets .tk` 的数量 ≠ 自选池注数 —— 池空但有选区时会多渲染一行「选区预览」，

## 2026-10-13 夜（二）改动：AI 出号「要 N 注就得 N 注」

### 病灶（源码级）

`normalize_ticket()` 原本**只校验号码范围，不校验个数**，靠 `bet_count() > 0` 兜底。结果：

| 模型给歪的样子 | bet_count | 表现 |
|---|---|---|
| 红球少给 1 个（5 个） | `0` | 整注**静默丢弃** → 「要 2 注只出 1 注」 |
| 号码含重复（去重后不足） | `0` | 同上 |
| 红球多给（7 个） | `C(7,6)=7` | 1 注**悄悄膨胀成 7 注复式** |
| 蓝球给 2 个 / kl8 选8 给 9 个 | 2 / 9 | 同上 |

### 改法

- `normalize_ticket_ex(code, play, t, strict_count)` → 返回 `(号码, 原因)`；
  `strict_count=True` 时**每区个数必须精确等于规格**（kl8 按玩法档位、组三=2、组六=3）。
  默认 `False` → **手工改号仍可复式**，只有 AI 出号走严格口径。
- `ai_pick_flow(code, play, prompt, sets)`（可单测）：**最多两轮**，首轮不足就把已给号码带上再要一轮并要求避开；
  重复注去重；超出要求则截断。
- `llm.SYS_PICK` 增补：每注个数一致、区内不重复、**tickets 必须正好 N 注、不要复式**。
- 前端：显示「你要求的是 N 注」；不足弹橙色警示条并列出原因；自动补足时给说明。

## 2026-10-13 夜（五）改动：投注倍数（倍投）

- **口径定案**：`sets` 存「含倍数后的总注数」，`amount = 单价 × sets`，倍数另存 `mult` 列 —— 这样「注数 × 单价 = 投入」在任何倍数下都成立
- **迁移**：`tickets` 加 `mult INTEGER DEFAULT 1`；`init_db()` 里 `PRAGMA table_info` 查列、缺则 `ALTER TABLE`，并把 NULL/异常值刷成 1（线上老库靠这步补上）
- `_mult_of()`：倍数非数字/越界一律收敛 1~99。原来直接 `int()` 会让 `mult='abc'` **报 500**
- `/api/bet`、`/api/ticket/update` 接 `mult`；`/api/pool/calc` 接 `mults[]` 并回 `per_amount`
- `settle_row()`：每个组合的中奖金额 **× mult**（= 单注奖金 × 倍数），命中明细标 `×N`
- 前端：自选池每行「倍投」输入框（改完重算该行+池底）、概览区「倍投倍数」（作用于选区直接记账）、账本明细显示 `N 倍`、修改弹窗可改倍数；发送前用 `numOnly()` 剥掉内部字段
- 验证：本地端到端 **33/33**、线上接口 **14/14**、线上浏览器 **21/21**

### 本机自测的坑：`http_proxy` 拦了本地回环请求

## 2026-10-13 夜（六）改动：投注概览 → 随机补全 · 出注

**需求**：原「投注概览」卡片信息冗余（注数/金额在自选池池底、概率在概率表页都有），改为
**补全号码随机出注**；「确认投注并记账」按钮移入**自选池（待记账）**卡片。

**功能定义**（`randPick()`）：

- 号码表里点选的号 = **保留号（胆码）**，出注时一定保留；
- 每个分区按 `zoneNeed(z)` 算差几个，**只随机补空缺位**，区内不重复；
- 一个号都不选 → 整注随机；
- 一次可出多注（每注都保留同一批胆码）→ 与「机选 / 按策略出号」（整注重新生成）分工不同。

**纯前端实现，无新接口**：号码规格（每区个数/范围）前端 `GAMES`（来自 `/api/games`）+ `zoneNeed()` 里全有，
与后端 `ai_spec()` / `need_count()` 是同一套规则。

**刻意选择：出注后不清空保留号**（`addToPool()` 是清空的）——保留号是"设定"不是一次性输入，
清空就没法连着出几批随机号；提示文案写明「保留号继续生效」，并指向自选池去确认投注。

**改动**：卡片标题与内容（新增 `#pc-keep` 动态提示 + 出几注 + 🎲 按钮；原 `#p-kpi` / `#p-advice`

## 2026-10-13 夜（七）改动：3D / 排列3 结算判不中（三个缺陷叠加）

原症状：`games.combos()` 展开出的是 `{'a':[2],...}`（**列表**），而 `hit_level()` 对 3d/pl3 直接拿
`ticket['a']` 与开奖的**标量**比 → `t == d` 永不成立，**中了也记成 +0**。

排查后确认是**三个**缺陷叠在一起（不止报告的那一个）：

| # | 缺陷 | 影响 |
|---|---|---|
| 1 | 直选：`ticket['a']` 是列表，开奖是标量 | 直选**永远**判不中 |
| 2 | 组选3：拿 2 个数字去和开奖的 3 位比（`t == d`） | 组选3 **永远**判不中 |
| 3 | `combos()` 对组选（号码存在 `'n'` 里，不在任何分位上）返回 `[]` | 组选复式不展开，多注变 1 注判定 |

根因一句话：**判定（标量）与展开（列表）两套接口形态没对齐**。

修法（`games.py` 两处，覆盖所有调用方）：

- 新增 `_digit_num(v)`：数字型彩种取值**兼容标量与长度 1 的列表**；`hit_level()` 的 digit 通用分支也改用它。
- 组选改成比**去重排序后的数字集合**（组选3 = 恰好 2 个不同数字，组选6 = 恰好 3 个），键名 `n` 与 `a/b/c` 两种形态都吃。
- `combos()` 增加 3d/pl3 组选分支：`{'n':[...]}` → `itertools.combinations(nums, 2|3)`，展开口径与 `bet_count()` 一致。

## 2026-10-13 夜（八）改动：出号策略去重 / 每组号码个数（复式）/ AI 点评移到自选池

### 1. 「机选 / 按策略出号」除反人群外，出几注都是同一组号 —— 已修

**根因（`analyzer.py`）**：`hot` / `cold` 走的是 `stats.hot()` / `stats.cold()`，
那两个函数返回的是**确定性的前 k 名**——同一次调用里出 N 注，每注都拿同一份结果。
`random` / `balanced` / `anti-crowd` 有随机性，所以只有它俩出重号。

**修法**：新增 `_weighted_pick(pool, weights, k, rng)` —— **按权重不放回逐个抽取**，
`hot` 权重 `(出现次数+1)³`、`cold` 权重 `(遗漏期数+1)³`。
> 关键：**不能**改成"取权重最高的前 k 个"，那还是确定性的，照样出 N 组一样的号。

同时 `generate()` 增加**同批整注去重**（`sigs`，最多重试 40 次），
所有策略（含 3D/排列3 组选、排列5、七星彩）都保证 N 注互不相同。
按位直选的 `hot`/`cold` 也补上了权重抽样——**之前 `hot` 在按位彩种里根本没实现**（等同纯随机）。

## 2026-10-13 夜（九）改动：概率改为「多注口径」

**起因**：蒋工问「多注投注，最高奖的概率是不是要有变化」。答案是**要变**——但程序三处
概率显示全是**单注**值（`total_win_prob()` / `top_prize_prob()` 只吃 `(code, play)`，与注数无关），
从 1 注加到 100 注数字纹丝不动，实际应差 100 倍。

### 1. 两种口径的数学差别（这是本轮的核心）

| 指标 | 公式 | 为什么 |
|---|---|---|
| **最高奖级** | `n × p`（**精确**） | 能中最高奖的只有那**唯一一个**开奖组合，n 注互不相同的号码就是覆盖了 n 个组合，命中概率正好 `n/T` |
| **任一奖级** | `1-(1-p)^n`（**近似**） | 能中奖的组合有很多、彼此重叠，n 注之间会「同时中」，不能简单相加；`n × p` 会把概率算大 |

双色球实测：5 注 → 最高奖 `5/17,721,088`、任一奖级 `29.34%`（**不是** 5 × 6.71% = 33.5%）。

### 2. 倍投不参与概率（最容易混的一点）

| 操作 | 中奖概率 | 金额 |
|---|---|---|
| **倍投**（同一个号买 N 倍） | **完全不变** | ×N |
| **多注不同号码** | ×N | 各注分别算 |

所以 `combTop(p, n)` 传的是 `sets`（注数）而**不是** `total`（含倍投）。前端并在倍投时补一句
「倍投只放大中奖金额，不改变中奖概率」。

### 3. 改了哪三处

| 位置 | 改动 |
|---|---|
| 选号区 KPI | 「任一奖级概率」「最高奖级概率」按本次注数放大，下方小字留**单注对照**（`单注 6.71% × 5 注`） |
| 机选/按策略出号后 | 尾部新增「**本次合计（N 注）**」，并保留「单注口径」一行对照 |
| 自选池池底 | 新增「**号码覆盖 K 注** · 中最高奖 1/Y · 任一奖级 Z%」；池内有**完全重复的组**时告警 |

**池内去重口径**：`tkSig()` 给每组号做签名（键名排序 + 号码排序），完全相同的组只算一次**号码覆盖**
（重复不增加中奖概率），但**金额照收**——重复的号等同倍投。覆盖数用 `r.per`（每组展开注数，不含倍数）累加。

### 4. 实现与验证

- **纯前端**（`static/index.html`）：新增 `combTop()` / `combAny()` / `tkSig()` / `topRow()`；
  `combAny` 用 `-Math.expm1(n * Math.log1p(-p))` 写 `1-(1-p)^n`，小概率下不丢精度
- 本地**无头 Chrome 23/23**、线上**无头 Chrome 23/23**（未选号 5 注 / 复式 7 注 ×7 / 倍投概率不变 /
  池内重复告警 / 覆盖 1→2 注 / 机选「本次合计」/ 无 JS 异常）
- 推送 `static/index.html` md5 本地/线上一致，**纯前端不用重启**；备份 `.bak/index.html.bak-20261013-multprob`
- 线上数据零影响：验证全程未调记账接口，清理后库计数回到 `users=2 / tickets=12 / ledger=2`

### 5. 顺带记一个测试教训

**线上验证不能用固定 `sleep` 等异步渲染**——本地 1.6 s 够，线上不够，会出现「假红」
（同一个用例第一次挂、第二次过）。本轮两次失败全是这个原因，改用条件等待（`waitFor` 到目标文本）后
本地/线上各 23/23 一次通过。

## 2026-10-13 夜（十一）改动：AI 出号也能设「每组号码个数」（复式）

### 记两个测试脚本的坑

1. **按"行数"删代码块会删歪。** 删一个 2 行的箭头函数时写了"删 3 行"，多删掉的正是
   下一个函数的函数头，`node --check` 直接报 `Unexpected identifier`。
2. **JS 正则里的 `\/` 经工具落盘会变成 `\\/`**（双反斜杠），正则语义整段变掉。
   规避办法：干脆不用正则 —— 改 `indexOf('/api/generate') >= 0` 这类普通字符串比较。
   写完先 `node --check` 再跑。

## 大模型（AI 建议 / AI 出号）

设置页「大模型配置」有两处**互相独立**的条件，缺一个 AI 功能就不可用：

1. **API Key**（留空表示不修改已存的）
2. **「启用」下拉** —— 默认是「关闭」，**必须切到「开启」再保存**

> 2026-10-13 的实例：Key 早已配好（`has_key: true`），但「启用」是关闭，
> 点「AI 建议」只报「未接入大模型」—— 排查时**先看 `GET /api/options` 里 `llm.enabled`**，
> 别一上来就怀疑 Key。前端现在会把这个错误翻成人话并指明去哪儿改。
